The application entry point (`src/index.ts`) bootstraps an Express server with global middleware (helmet, cors, rate limiting, JSON parsing) and mounts the aggregated router at `/api`. The router (`src/routes/index.ts`) composes domain-scoped route files (auth, users, victims, social-workers, organizations, incidents, cases, appointments, services, messages, notifications, analytics), each of which pairs a `routes/*.ts` file with a matching `controllers/*.ts` handler. Cross-cutting concerns are centralized in `src/middleware/`: `auth.ts` validates Bearer tokens, `rbac.ts` enforces role-based access, `validate.ts` performs request-body schema validation, `errorHandler.ts` catches unhandled errors, and `upload.ts` handles file uploads; these are applied per-route or globally by the controllers. Configuration is loaded from `src/config/env.ts` and Prisma database connection is initialized via `src/config/database.ts`, giving all controllers a shared data layer. Domain utilities (`utils/caseNumber.ts`, `utils/password.ts`, `utils/token.ts`) provide reusable helpers consumed across multiple controllers.
