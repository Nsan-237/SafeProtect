Built as a Next.js 14 App Router application with a single root layout (`src/app/layout.tsx`) and a protected `(dashboard)` route group whose `layout.tsx` wraps every feature page in a `DashboardLayout` composed of `Sidebar`, `Header`, and a `<main>` outlet. Feature pages live under `src/app/(dashboard)/<feature>/page.tsx` (appointments, cases, dashboard, incidents, messages, organizations, reports, settings, social-workers, users, victims) and are rendered client-side via the `'use client'` directive. Authentication is enforced at two layers: a Next.js middleware (`src/middleware.ts`) redirects unauthenticated requests to `/login` based on an `accessToken` cookie, while each client page also checks `localStorage('@token')` as a secondary guard. API calls go through a shared Axios instance (`src/lib/api.ts`) that injects Bearer tokens from `localStorage('@token')` and implements automatic 401 refresh-token rotation against `/auth/refresh-token`. Domain models are centralized in `src/types/index.ts` (User, Incident, Case, Victim, SocialWorker, Organization, Appointment, MessageThread, Message). UI is built from a small shadcn-style component library under `src/components/ui/` (avatar, badge, button, card, input, table), reusable chart components under `src/components/charts/` (Recharts-based), and domain-specific presenters under `src/components/dashboard/`. Styling uses Tailwind CSS configured via `tailwind.config.ts` and PostCSS.
